# UX-принципы

Десять правил, которые решают споры. Если фича им противоречит - фича плохая.

1. **Один экран = редактор.** Никаких панелей файлов, превью и дашбордов на старте.
   Файлы открываются через [[Экран - Открытие файла]].
2. **Вкладки, не сплиты.** Сплиты - антипаттерн для нашего workflow. Переключение -
   `Alt-J/K`, клик по вкладке.
3. **Нет мод.** Буквы всегда вводят текст. Действия - на `Ctrl-*`, `Alt-*` и `F-*`.
4. **Мышь - первый класс, но не обязателен.** Любое действие мышью дублируется клавишей
   (паритет), иначе мышью пользуются только наполовину.
5. **Esc - это отмена, не выход.** Esc закрывает оверлей, затем снимает выделение, затем
   гасит ghost. Выход - `Ctrl-Q`.
6. **Ничего не теряется.** Dirty-флаг, backup несохранённого, вопрос при внешнем изменении
   файла. Молча перезаписать нельзя.
7. **Подсказки не живут в буфере.** Ghost-текст, popup, подсветка - всё в слое отрисовки.
   Буфер, undo и файл на диске видят только настоящий текст.
8. **Prose и Code - разные режимы поведения, один интерфейс** (см. [[Prose и Code]]).
   Русский/английский и markdown-фичи включаются везде, где файл не код.
9. **Русский и английский - равные граждане.** Ширина символов, спеллчек, «ё», переносы.
   Никакой ASCII-only логики.
10. **Быстро на глаз.** Отрисовка только видимого, события - в одном цикле, никаких
    блокирующих вызовов в UI-потоке.

## Что это значит для реализации

- Любой экран описывается как [[Примитив - Popup]] + [[Примитив - Строка ввода и список]]
  или как зоны [[Экран - Редактор]].
- Фокус всегда один: текст, попап или строка ввода. Клавиши идут сверху вниз:
  help → popup → input → текст (см. [[Архитектура]]).
- Действия не дублируются в разных местах: правка текста - только в буфере, а не в ghost.
