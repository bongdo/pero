# Примитив - Markdown-чекбокс и списки

## Зачем

`todo.md` - основной файл. Чекбоксы ставятся и снимаются одной клавишей, списки
продолжаются сами.

## Чекбокс

```
- [ ] задача
- [x] сделано
```

- `Alt-t` на строке: нет префикса → `- [ ] `; `- [ ] ` → `- [x] `; `- [x] ` → `- [ ] `.
- Работает после любого отступа: отступ сохраняется.
- Голый `[ ] ` тоже переключается (наследство micro), но при вводе нового ставим `- [ ] `.

Почему именно `- [ ]`: ltex (LanguageTool) режет `[ ]` как markdown-чекбокс и оставляет
двойной пробел - правило `WHITESPACE_RULE` срабатывает на каждом переносе строки. С `- [ ]`
этого нет. Проверено на живой ltex.

## Списки

- `Enter` в конце строки-списка (`- `, `1. `, `* `) продолжает список с тем же маркером.
- `Enter` на пустом пункте - убирает маркер и оставляет пустую строку.
- `Tab`/`Shift-Tab` - вложенность (2 или 4 пробела по `tabsize`).
- `Alt-s` - схлопнуть повторные пробелы в строке (косметика, но частая).

## Состояния

| Ситуация | Поведение |
|---|---|
| Курсор в середине строки | чекбокс ставится в начало после отступа |
| Уже `- [x]` | переключается на `- [ ]` |
| Строка не список | `Alt-t` добавляет `- [ ] ` в начало |
| read-only | `Alt-t`/`Alt-s` игнорируются |
| Не markdown | фичи выключены (см. [[Prose и Code]]) |

## Крайние случаи

- Отступы табами - сохраняем как есть, не конвертируем.
- Чекбокс в цитате (`> - [ ]`) - v1: не поддерживаем, ставим в начало строки.
- Список внутри кода (```` ``` ````) - не трогаем, определяем по ограждению.
- Unicode-маркеры (`•`, `✓`) не используем, только ASCII.

## Критерии готовности

- [ ] `Alt-t` циклит `- [ ]` ↔ `- [x]`, отступ не съедает.
- [ ] `Enter` продолжает список, пустой пункт - выходит из списка.
- [ ] `Alt-s` не трогает отступ.
- [ ] В `.go` файле `Alt-t` ничего не делает.
