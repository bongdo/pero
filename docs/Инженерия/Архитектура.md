# Архитектура

Черновик. UX описан раньше и важнее: если архитектура мешает экранам - меняем архитектуру.

## Стек

- Go 1.26, `charm.land/bubbletea/v2`, `charm.land/bubbles/v2`, `charm.land/lipgloss/v2`.
- Тот же стек, что у [[Референс - felix-tui]], проверен на живом проекте.
- Bubble Tea - Elm-цикл: `Update(msg) (Model, Cmd)`, `View() tea.View`. Никаких горутин,
  которые меняют модель: всё через сообщения.

## Пакеты

```
main.go                 аргументы, bootstrap
internal/ed/            буфер, позиция, транзакции, undo, файл (Editor Core)
internal/ui/            модель, layout, render, overlay, theme, тосты (Presentation)
internal/input/         клавиши, мышь, фокус (Input)
internal/lsp/           JSON-RPC клиент, диагностики, completion, code action
internal/assist/        ghost, t9, будущий AI
internal/workspace/     вкладки, проект, сессия, state
internal/config/        TOML, темы, биндинги
```

Имена пакетов - по контекстам из [[Контексты]], а не по типам.

## Цикл

```
tea.KeyPressMsg → input.Route → команда домена → ed.Transaction → Changed
                                              ↘ lsp.DidChange (async)
lsp.Msg (диагностика/кандидат/фикс) → ui.Update → render
```

- Ввод никогда не ждёт LSP.
- Правки - только через `ed` (транзакции), включая LSP-фиксы и AI-вставки.
- Undo - часть `ed`, а не UI.

## Команды

- Каждое действие - команда: `id`, название, клавиша-подсказка, функция.
- Клавиши не содержат логики: они находят команду по id и запускают её.
  Одна и та же команда доступна из `Ctrl-E`.
- Команда, которой не хватает условий (нет LSP, нет фиксов), не показывается в палитре.
- Реестр - единственное место, где перечислены действия; help строится из него же.

Это делает поведение предсказуемым: если действие есть на клавише, оно есть и в палитре,
и наоборот.

## Рендер

1. `layout()` считает прямоугольники из размера терминала (как `felix-tui/internal/ui/layout.go`).
2. Буфер → видимые экранные строки (softwrap), гаттер, статус, вкладки → `[]string`.
3. Оверлеи (popup, меню, помощь) вставляются в готовые строки ANSI-безопасно
   (`felix-tui/internal/ui/dialog.go:551 renderOverlays`, `overlayAt`).
4. `tea.View{Content: ...}`.

Отрисовываем только видимое; полный пересчёт - только при ресайзе/смене вкладки.

## Текст

- Логические строки `[]rune`; позиция (строка, руна).
- EOL и BOM - свойство документа, не текста.
- Транзакция: список обратных операций + курсор до/после. Все правки (ввод, paste, LSP,
  replace-all, ghost-accept) - транзакции.
- Большие файлы: лимит (10 МБ), read-only выше.

## LSP

- Один процесс на (язык, проект). JSON-RPC через stdin/stdout.
- Запросы с id, ответы сопоставляются по id (в micro-плагине был один слот - здесь делаем
  нормально).
- Диагностики кэшируются по URI и версии документа; code action отправляет их обратно как
  есть (сырой JSON), иначе ломается юникод/экранирование - проверено на micro.
- Падение сервера - не падение редактора: статус `LSP off`.

## Assist

- Ghost: отдельное состояние `suggestion{range, text, source, version}`; рендер - слой 5
  ([[Примитив - Диагностика и ghost]]). Принятие - транзакция.
- t9: индекс слов буфера, обновляется лениво; кандидаты по префиксу, частота.

## Тесты

- `ed`: property-тесты на вставку/удаление/undo, unicode.
- `ui`: золотые экраны (layout + render) для 40×10, 80×24, 160×50.
- `lsp`: фейковый сервер на stdin/stdout, без реальных процессов.
- Всё, что можно, - без терминала.

## Что уже решено (см. [[Решения]])

- Свой буфер, не `bubbles/textarea` (в нём нет гаттера, подсветки, ghost).
- Overlay-композитор - свой, приём из felix.
- Конфиг TOML + state отдельно.
